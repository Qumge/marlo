# CI 的依赖锁。【不要手改】——用下面那条命令重新生成。
#
# 【为什么要有它】pyproject 里 16 个依赖没有上界，于是"上游哪天发大版本"
# 就是我们的定时炸弹。2026-07-28 mcp 2.0.0 一发布，CI 立刻装上它，而 2.0 删掉了
# streamablehttp_client —— 几乎每个测试模块 import 就失败。CI 连红三次，
# 而那三次【一条测试都没有真正执行过】：它不是在报告失败，是什么都没测。
#
# 逐个钉上界能挡住这一类，但代价是挡住安全补丁、制造解析冲突，而且每加一个
# 依赖都要有人记得钉。锁文件把这件事反过来：CI 装的永远是这里写死的版本，
# 依赖升级变成一次【明确的、能被审阅的改动】，不是某天早上的意外。
#
# 【平台】按 CI 的环境解析（Linux + Python 3.12），不是本地的 macOS + 3.14 ——
# 用本地 pip freeze 出来的锁在 CI 上是错的（平台轮子和可用版本都不同）。
#
# 【本地开发不受影响】：本地照常 pip install -e ".[messaging,dev]"，
# 装到的可能比锁里新。两边不一致时，以 CI 为准 —— 它才是发版走的那条路。
#
# 【怎么更新】（比如要升 mcp 到 2.x）：
#   1. 先改 pyproject 里的约束
#   2. uv pip compile pyproject.toml --extra messaging --extra dev \
#        --python-version 3.12 --python-platform linux -o requirements-ci.txt
#   3. 本地按新版本装一遍，把测试真跑过再提交 —— 锁文件绿不代表代码适配了新 API
#
